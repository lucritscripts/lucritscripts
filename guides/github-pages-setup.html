Ship a site on GitHub Pages in 10 minutes

Web · 6 min read

GitHub Pages serves static files straight out of a repository, free, with HTTPS. If your site is HTML, CSS and JavaScript, you do not need a host. Here is the whole path.

1. Create the repository

Make a new public repo. The name only matters in one case: if you name it your-username.github.io, the site lands at the root of that domain. Any other name puts it at your-username.github.io/repo-name/.

2. Put an index.html at the root

Pages looks for index.html in whichever folder you publish from. No build step, no framework required.

<!doctype html>
<html><body><h1>It works</h1></body></html>

3. Turn Pages on

Repo → Settings → Pages → under Build and deployment, set Source to Deploy from a branch, branch main, folder / (root). Save. First deploy takes a minute or two.

The three things people get wrong:
  1. Missing .nojekyll. Without it, Pages runs Jekyll and silently ignores any folder starting with an underscore.
  2. Absolute paths. /assets/style.css breaks on project sites. Use relative paths like assets/style.css.
  3. Case sensitivity. Pages is case-sensitive; your local machine probably isn't. Style.css ≠ style.css.

4. Custom domain (optional)

Add a CNAME file containing just your domain, then point DNS at GitHub: a CNAME record for www → your-username.github.io, or four A records to GitHub's Pages IPs for the apex. Tick Enforce HTTPS once the certificate provisions.

5. Know the limits

  • Static only — no server-side code, no databases, no secrets.
  • Soft limits: 1 GB repo, 100 GB/month bandwidth.
  • Anything needing a hidden API key belongs in a serverless function, not the repo.

Starter pack

  • pages-template.zip — repo scaffold with .nojekyll, workflow, and a clean base stylesheet.
  • dns-cheatsheet.pdf — every record type you might need, with real examples.
  • preflight.md — 12-point check before you announce the site.

Replace these with your own files in assets/downloads/.

Wrapping up

Push, wait sixty seconds, load the URL. If you get a 404, it is almost always one of the three mistakes above.
